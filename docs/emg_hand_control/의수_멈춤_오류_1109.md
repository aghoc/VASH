# 의수 실행 중 멈춤·시작 실패 기록 (2026-11-09, Windows PC + U2D2 COM7)

세손가락 데모(`start_hand.py --demo --demo-grip tripod ...`)를 반복 실행하면서 생긴 문제들. 원인이 확인된 것과 안 된 것을 나눠 적는다.

## 1. 시작 실패: ID 14 중립 목표가 캘리브레이션 범위 밖
- 증상: `RuntimeError: ID 14: neutral waypoint outside calibrated motor limits`
- 원인 (확인): 손을 다른 컴퓨터(Jetson)에서 쓰고 온 뒤 ID 14(엄지 벌림) 모터 위치가 1.93 rad 로, 이 PC 의 `calibration.yaml` 범위(0.91–1.82 rad) 밖. 백업 캘리브레이션 10 개 어느 것과도 맞지 않음
- 조치: 이 PC 에서 `start_hand.py --calibrate --calibrate-only` 로 장력·캘리브레이션 다시 함 (16/16, 이동량 기준 이내)
- 주의: `calibration.yaml` 은 손·장력 상태마다 다르므로 이 저장소에는 새 값을 올리지 않음. 손을 다른 컴퓨터로 옮기면 그 컴퓨터에서 다시 캘리브레이션하거나 그 컴퓨터의 파일을 복사

## 2. 시작 실패: 중립 도착 검사에서 ID 14 만 3° 초과
- 증상: `중립 도착 실패 — 많이 벗어남 ['ID 14 3.4°']`
- 원인 (확인): 한도가 모든 모터 같은 3°(모터 각도). ID 14 는 모터 범위가 약 52° 로 좁아 3° 가 범위의 6 % (MCP 133° 는 2 %). 중립 50° 가 관절 범위 끝(55°) 근처라 장력에 막혀 덜 감 (모터는 멈춤 상태, 하드웨어 오류 없음)
- 조치: `start_hand.py` 중립 한도를 모터별로 — 캘리브레이션 범위의 8 %, 최소 3°, 최대 5° (ID 14 = 4.2°). 하드웨어 오류가 있으면 멈추는 것은 그대로

## 3. 시작 실패: 토크가 켜진 채 남음
- 증상: `hold_tension.py`: `ID 2: 다른 프로그램이 모터를 쓰고 있어요 (토크가 켜져 있음)`
- 원인 (확인): 앞 실행이 비정상 종료(아래 4)되면서 토크 해제를 못 함. 손을 쓰는 프로그램은 없었음
- 조치: 모터 16 개 토크만 끄고 확인한 뒤 다시 실행. 비정상 종료 뒤에는 항상 토크 상태 확인 필요

## 4. 실행 중 멈춤: 모터 버스 응답 끊김 → USB 시리얼 '액세스 거부' (원인 미확인)
- 증상 (11-09 18:12, 18:26, 두 번 모두 데모 시작 몇 분 안):
  ```
  RuntimeError: motor position read failed: the motor bus returned no status packets
  ...
  serial.serialutil.SerialException: ClearCommError failed (PermissionError(13, '액세스가 거부되었습니다.'))
  RELEASED: torque off verified for 0/16 motors.
  RuntimeError: Torque release unconfirmed for [2..17]; disconnect motor power
  ```
- 결과: 종료 처리에서 토크를 못 꺼서 손이 마지막 자세에 토크 켜진 채 남음
- 확인한 것:
  - 직후 COM7 다시 열림, 모터 16 개 응답·하드웨어 오류 없음, 전압 11.8 V
  - Windows 장치 제거(PnP) 기록 없음 → 운영체제 기준으로 USB 장치가 빠진 것은 아님
  - 같은 PC 의 통합 앱 서버는 COM 포트 목록만 보고 COM7 을 열지 않음
  - 그 시각에 다른 프로그램이 COM7 을 연 흔적 없음
- 의심 (미확인): U2D2 USB 케이블·허브 접촉, 모터 전류가 크게 바뀔 때 전원·접지 잡음으로 U2D2(FTDI) 가 순간 리셋
- 확인 방법 제안: USB 를 PC 본체 포트에 직접(허브 없이), 짧은 케이블로 바꿔 같은 데모 10 분 이상. 모터 전원과 PC 접지 공유 확인. 다시 나면 시각과 `neutral_result.json`·기록 CSV 마지막 줄 확인
- Ctrl+C 로 끌 때도 같은 `ClearCommError` 가 한 번 나옴 (종료 동작 중 신호가 시리얼 호출을 끊음). 끈 뒤 토크 상태를 꼭 확인

## 5. 시작 실패: ID 12(소지 MCP) 과부하 오류
- 증상: `ID 12: expected XC330-T288-T, got 1220; comm=0, error=128` (상태 패킷 alert 비트)
- 레지스터 70 Hardware Error Status = 32 (과부하). 온도 32 °C, 전압 11.8 V 정상, 다른 모터 오류 없음
- 조치: ID 12 재부팅(Reboot 명령)으로 오류 지움 → 오류 0, 토크 꺼짐, 제어 모드 5 그대로
- 원인 (미확인): 세손가락 자세에서 소지 MCP 가 −13°(펴는 쪽)로 명령됨 → 소지가 펴진 채 걸려 계속 밀었을 가능성. 4 번 버스 끊김과 관련 있는지 모름. 다시 나면 세손가락에서 약지·소지 squeeze 를 빼는 쪽으로
